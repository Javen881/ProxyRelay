# Android 热点代理中继：连接方案与排查

## 目标与环境

手机连接 VPN 后，让连接手机热点的笔记本通过内网 SOCKS5 代理访问内网服务，无需 Root。

已知地址：

| 项目 | 地址或说明 |
| --- | --- |
| 内网 SOCKS5 代理 | `192.168.10.3:7892` |
| 手机 VPN 虚拟接口 | `192.168.9.2` |
| 手机中继监听地址 | 默认 `0.0.0.0:17892` |
| 手机热点 IP | 尚未确认，通常是笔记本连接热点后获得的默认网关 |

## 正确连接路径

```text
笔记本上支持 SOCKS5 的应用
    ↓ 连接手机热点 IP:17892
手机上的 ProxyRelay 中继应用
    ↓ 新建出站 TCP 连接，由手机 VPN 路由
内网 SOCKS5 代理 192.168.10.3:7892
    ↓
内网目标服务
```

中继应用接收笔记本连接后，另行建立到上游代理的连接，双向透传 TCP 字节。它不修改系统路由，不需要 Root，也不创建第二个 VPN。

手机 VPN 必须允许中继应用的出站连接经过 VPN。如果 VPN 按应用分流，应包含“内网代理中继”。

## 当前问题与结论

现象：笔记本可以到达 `192.168.9.2`，但无法连接 `192.168.9.2:17892`。已确认 `192.168.9.2` 是手机 VPN 虚拟接口地址。

应优先使用手机热点 IP 作为笔记本的代理入口。VPN 接口地址属于隧道侧，不应据此假定它适合作为热点客户端的服务入口。能 ping 通某个地址，不代表该地址上的 TCP 端口一定可达。

但目前没有完整的连接错误与日志，不能断言“VPN 接口地址一定无法监听”，也不能认定更换地址就一定解决问题。监听 `0.0.0.0` 表示监听所有本机 IPv4 地址，但可达性仍受路由、VPN 策略和系统防火墙影响。

下一步应将笔记本代理地址改为手机热点网关 IP，端口保持 `17892`。如仍失败，再区分监听失败、入站被阻止和上游不可达。

## 配置方法

### 手机

1. 连接 VPN，并开启系统热点。
2. 打开“内网代理中继”。
3. 设置上游地址 `192.168.10.3`、上游端口 `7892`。
4. 设置监听地址 `0.0.0.0`、监听端口 `17892`。
5. 保存配置并启动，确认界面显示“正在监听”。
6. 若 VPN 按应用分流，将中继应用纳入 VPN。

`0.0.0.0` 是监听配置，不是笔记本应填写的目标地址。只需要热点访问时，也可将监听地址设为实际热点 IPv4；热点地址变化后需重新配置。

### 笔记本

查看当前连接手机热点的网络详情，找到 IPv4 默认网关。Windows 可用 `ipconfig`；Linux 可用 `ip route`；macOS 可在网络设置的 TCP/IP 页面查看“路由器”。存在多个网络连接或 VPN 时，应查看热点对应网卡的信息。

填写：

| 配置项 | 值 |
| --- | --- |
| 代理类型 | SOCKS5 |
| 代理地址 | 手机热点 IPv4／热点对应网卡的默认网关 |
| 端口 | `17892` |
| 认证 | 沿用内网 SOCKS5 的账号密码，如有 |
| 内网域名解析 | 尽量交给代理端解析 |

不要填 `192.168.10.3` 作为手机中继入口，也不要把 `0.0.0.0` 填入笔记本代理地址。`17892` 是 SOCKS5 入口，不能当作 HTTP 网站直接在地址栏打开。

## 排查分层

| 状态或现象 | 含义与检查方向 |
| --- | --- |
| 尚未启动／启动失败 | 本机未正常监听，检查日志、监听 IP 和端口占用 |
| 正在监听，但 TCP 连接被拒绝 | 检查目标 IP、服务是否仍运行，以及系统是否主动拒绝 |
| 正在监听，但 TCP 连接超时 | 检查热点 IP、路由、VPN 的局域网限制与防火墙 |
| 出现“连接上游失败” | 笔记本连接已进入中继，检查中继应用的 VPN 分流和上游可达性 |
| 出现“已连接上游”，但业务失败 | TCP 上游已建立；继续检查 SOCKS5 认证、内网 DNS 和目标服务 |

首版收到客户端连接后，不会立即记录“已接入”，而是等上游连接成功或失败才记录。默认连接超时为 10 秒，因此短时间没有日志不能证明客户端没有连接进来。

手机浏览器可以访问内网，并不证明中继应用也能访问；按应用 VPN 分流可能使两者走不同网络。

## 首版待改进项

以下是已识别的改进方向，并非已实现功能：

- 区分 VPN 接口和热点候选接口，避免把所有接口都展示为同等推荐的连接地址。
- 无法可靠识别热点时，明确引导用户查看笔记本热点网卡的默认网关。
- 接受客户端连接后立即记录来源与时间，再分别记录上游连接结果。
- 将“监听成功”和“上游连接成功”显示为不同状态，避免误认为整个链路已经打通。

## 能力边界与验证状态

- 支持 TCP 透传，不支持 SOCKS5 UDP 转发、ping 或自动接管笔记本全部流量。
- 不保证 VPN 断开时阻止直连；出站遵循系统为中继应用选择的网络。
- 热点网段与目标内网网段应避免重叠。
- 默认监听全部 IPv4 接口，只应向可信设备开放；中继不额外增加认证。
- 本地 APK 构建、签名校验和 TCP 核心测试已通过，Lint 无错误。
- 手机 UI、后台运行及实际 VPN 链路尚未完成真机验证；热点入口地址仍待确认。
